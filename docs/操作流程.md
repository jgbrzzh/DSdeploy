# 新版完整操作教程

适用 v1.4.0。可先阅读包根目录的 [先看这里](../先看这里.md)。本教程按首次安装顺序编排，后半部分说明独立升级、备份和排错。旧版完整迁移请使用单独的迁移指南。

## 1. 准备与下载

- 支持 Docker Desktop / WSL2 的 Windows 10/11，使用 Linux containers。
- 建议 8 GB 以上内存、至少 25 GB 可用磁盘；双实例需额外内存与各自的模型空间。
- 准备主人 QQ、机器人小号，以及可用的模型 API Key。两个版本同时在线请用不同机器人 QQ，避免顶号。
- 网络需能下载镜像/依赖/本地记忆模型，并访问 DeepSeek 服务。

从 [Releases](https://github.com/jgbrzzh/DSdeploy/releases/latest) 下载 DSdeploy-v1.4.0-windows.zip 和 SHA256SUMS.txt。包约 171 MiB，包含两套表情资源，不包含 Docker 镜像、QQ 程序或模型权重。

已有本项目任何标准旧版本、希望保留原配置和全部本地记忆时，请先用 [旧版本一键迁移指南](旧版本一键迁移指南.md)，不要执行下方的全新配置导入。迁移只需要输入旧部署目录。

可在下载目录核验：

```powershell
Get-FileHash .\DSdeploy-v1.4.0-windows.zip -Algorithm SHA256
```

与 SHA256SUMS 中同名摘要比较，再解压整个包。不要在 ZIP 预览窗口运行脚本。

## 2. 保留旧版，新版放新目录

例如旧版在 D:\Bots\Whale-old，新版放 D:\Bots\Whale-new。旧版目录、配置、数据与入口全部保留，不覆盖。

新版选择固定可写目录，找到 Deploy.ps1 和各个 cmd 入口。不要把旧版的 private/instance.json 复制过来，也不要用链接让两个实例共用 data。

双击“实例设置.cmd”。它会生成：

| 文件 | 用途 |
|---|---|
| private/instance.json | 本目录独立项目、镜像标签和端口 |
| private/本实例面板地址.txt | 本实例 AstrBot 与 NapCat 地址 |

新版默认不占旧版 6185/6099。实例身份绑定目录，安装后不要随意移动文件夹。需要指定端口或迁移业务副本时先阅读 [多版本隔离](多版本隔离.md)。

## 3. Docker：已有就复用

**已有 Docker（包括旧版用的 Docker）：**直接启动它，等待引擎运行。不要安装第二套，也不要为新版迁移旧版的数据盘。业务数据和容器各自隔离，Docker 引擎与电脑资源共享。

**没有 Docker：**双击“安装Docker.cmd”。官方安装器下载到 runtime/downloads，程序目标为 runtime/DockerDesktop，WSL 数据盘目标为 data/docker-desktop。按安装器完成虚拟化/WSL2 设置；如提示重启，先重启。

打开 Docker Desktop，确认 Linux containers 已就绪。系统仍会保留必要的 Windows 注册设置和日志，本包不是无需安装的便携程序。

## 4. 只准备镜像，不填账号

双击“下载准备镜像.cmd”。它会：

1. 首次下载或导入 AstrBot、NapCat、Ollama，保存镜像锁。
2. 构建四个插件所需依赖。
3. 准备本地记忆模型 bge-m3，约 1.2 GB；无需独显。

此步不要求 QQ 或 API Key，不生成机器人配置，不启动 QQ。下载失败时保留报错，再运行同一入口重试。已有镜像锁时继续使用原版本，明确升级上游才使用“更新镜像.cmd”。

默认镜像入口为 DaoCloud。必要时在本部署目录运行：

```powershell
powershell -File .\Deploy.ps1 -Action PrepareImages -ImageSource 1ms
# 明确升级并换源
powershell -File .\Deploy.ps1 -Action UpdateImages -ImageSource Official
```

在另一台联网 Docker 电脑使用“下载镜像包.cmd”导出基础镜像，带回 offline 文件夹后再运行准备入口。见 [离线搬运说明](../offline/下载说明.md)。插件依赖、向量模型与聊天服务仍可能需要网络，不等于完全离线。

## 5. 只导入配置，不下载镜像

双击“导入初始配置.cmd”，填写：

| 提示 | 填什么 |
|---|---|
| 主人 QQ | 你的日常账号，默认私聊和主动陪伴目标 |
| 机器人 QQ | 准备用 NapCat 登录的小号，不能和主人相同 |
| 群号 | 可选，逗号分隔。不填只开放主人私聊 |
| API 地址 | 官方默认 https://api.deepseek.com/v1 |
| 模型名 | 官方 V4.1 Flash 填 deepseek-flash，不是产品展示名称 |
| API Key | 你自己的 Key，输入时隐藏 |
| 官方搜索 Key | 聊天地址为第三方时才另询问；官方聊天 Key 自动填入独立搜索字段 |

此步创建模型、OneBot、主人权限、大肥鱼人设、记忆和陪伴设置，装入两套公开图库并默认同时选择。不启动机器人，不重下镜像。

已有配置保留；要改变旧默认陪伴设置使用专门升级入口。不要把 Key 贴进 QQ、公开 Issue 或截图。

## 6. 启动并扫码

双击“一键启动.cmd”。它只启动本地准备好的环境，缺少镜像或配置会提示对应入口，不会暗中导入或重新下载。

面板地址以 private/本实例面板地址.txt 为准，不使用旧版固定端口。凭据见 private/面板登录信息.txt：

- AstrBot 用户名 astrbot，使用随机初始密码。
- NapCat 使用随机 Token，然后扫码登录刚填写的机器人小号。

完成 QQ 设备验证。以后在面板更改的密码以面板为准，初始凭据文件不会跟随更新。

OneBot 已设置为容器内 ws://astrbot:6199/ws；这是同一实例网络的服务名，不要改成容器内 127.0.0.1。各实例的同名服务位于不同网络。

## 7. 在 QQ 逐项验收

**聊天：**用主人 QQ 加机器人好友，私聊“你好，大肥鱼”。真实收到回复才算成功；只打开网页不算通过。

**记忆：**说“请记住我喜欢无糖茶”，观察记忆工具是否保存成功；重启该实例或新建对话后再询问。自动总结默认每 10 轮触发，不等于每一句都会立即入长期记忆。不要把测试记忆写到旧版真实库。

**表情：**新部署已有大肥鱼 138 张、菲比啾比 101 张。在 meme_manager 管理页确认两套库和默认绑定；选择一个或同时选择两个。情绪判断并不保证每句话都发图，最多 1 张、默认概率 80%。已有新版实例可点“导入内置表情库.cmd”，不覆盖同名库或原选择规则。见 [图库来源](../meme-packs/README.md)。

**搜索：**说“请先搜索 AstrBot 的最新版本，再回答并附来源”，或让它阅读公开网页。需要看到 web_search_deepseek / deepseek_fetch_web_page 的实际工具记录与结果，不能只听角色自称搜过。已有新版实例点“配置DS联网搜索.cmd”；官方搜索 Key 与聊天字段独立，第三方聊天 Key 不自动复用。搜索/正文提取按官方规则独立计费，见 [DS 搜索说明](DS联网搜索.md)。

**主动陪伴：**默认主人私聊，间隔 120–240 分钟，23:00–08:00（北京时间）免打扰，最多 3 次未回复。首次自动检查还有等待时间，不会启动后立即来一句。检查会话名单和时段，再观察 QQ 实际收到主动消息；调度器显示已启动不等于消息已送达。

## 8. 日常与独立升级

| 需求 | 入口与流程 |
|---|---|
| 日常启动/停止 | 本目录“一键启动/一键停止”，只管理本实例 |
| 查看状态/错误 | 查看状态 / 查看日志；Ctrl+C 结束日志跟随 |
| 更换聊天模型或 Key | 在本实例 AstrBot 面板保存，启动不覆盖回旧输入 |
| 改个人口吻 | AstrBot 人格页编辑 dafeiyu；不会自动替换自定义人设 |
| 升级程序 | 仅对已具有 instance.json 的新版实例：先备份、停止，再覆盖程序文件，保留 data/private/runtime/backups/镜像锁 |
| 新版有依赖变化 | 下载准备镜像；沿用基础镜像锁，按需重新构建 |
| 改陪伴预设 | 升级陪伴配置；先备份，保留身份、Key、自定义人格与时段 |
| 主动换上游镜像 | 更新镜像，然后一键启动；旧锁保存到 backups |
| 补内置图库/搜索 | 导入内置表情库 / 配置DS联网搜索，不重下镜像 |

原 v1.0 保持原入口；不要把本版启动器直接覆盖到无实例身份的旧目录。需要旧数据副本请按 [多版本隔离](多版本隔离.md) 显式建立新身份。

第三方插件已有源码不会被部署包强制覆盖，插件版本升级按 AstrBot 插件页及对应上游说明执行。不要同时叠加多套主动调度或自动表情插件。

## 9. 备份与恢复

“备份数据.cmd”先暂停本实例，压缩后恢复原来运行的服务。backups 中包含业务数据、凭据及镜像锁；不含 Docker VHD 或可重新下载的模型。备份含聊天、Key 和 QQ 登录状态，不可公开分享。

同目录恢复：先停止该实例，将当前业务数据和 private 改名保留，再按备份原路径恢复，确认 instance.json 仍对应本目录后启动。不要用业务 ZIP 替换 Docker 数据盘。跨目录迁移需要重新建立实例身份；新版数据库可能已迁移，不能直接覆盖回旧版。

## 10. 常见问题

| 现象 | 处理 |
|---|---|
| 提示 Docker 未就绪 | 先启动 Docker Desktop，等待 Linux 引擎运行 |
| 旧数据没有实例身份 | 保留旧目录，另开空目录安装；数据副本按隔离说明处理 |
| 实例身份属于另一目录 | 不复制 instance.json；迁移副本先改名保留旧身份再建立新身份 |
| 面板端口冲突 | 查看本实例地址，停止该实例后按隔离说明改其端口，不停止旧版让位 |
| 下载超时/EOF | 在准备入口重试或更换镜像源，不重填配置 |
| bge-m3 非公网地址错误 | 查看 Fake-IP 修正日志，检查代理/DNS；本包不改系统 DNS，也不关闭地址校验 |
| QQ 在线但不回复 | 检查小号、反向 WS、当前模型、白名单；先主人私聊，再放行群 |
| API 401/402/429 | 分别检查 Key、余额、频率/额度；看实际错误正文 |
| 搜索有结果但读网页失败 | 先换免登录公开网页，目标网站可能阻止抓取 |
| 没主动消息或没表情 | 检查会话/时段/未回复上限、图库绑定和概率，不把启动成功等同发送成功 |

提交问题只提供系统/镜像版本、出错步骤、脱敏错误片段。不要上传 private/data/backups、二维码、真实聊天或完整凭据。已测试与未测试范围见 [验证记录](验证记录.md)。
