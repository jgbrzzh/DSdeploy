# 从下载到 QQ 聊天的完整操作流程

本指南面向 Windows 用户。无需手动安装 Python、Git 或插件依赖；运行环境由 Docker 镜像提供。

## 1. 准备条件

| 项目 | 要求 |
|---|---|
| 系统 | 支持 Docker Desktop / WSL2 的 Windows 10 或 Windows 11，使用 Linux containers |
| 内存 | 建议至少 8 GB，16 GB 更宽裕；默认使用 CPU，不要求独立显卡 |
| 磁盘 | 建议预留至少 25 GB 可用空间；镜像、构建缓存及模型体积远大于部署 ZIP |
| 网络 | 可下载 Docker 组件和 bge-m3，并可访问聊天模型 API |
| QQ | 一个用于机器人的小号，以及你日常使用的主人 QQ；两者不要填成同一个 |
| 模型接口 | 自备可用且有余额的 API Key；默认接 DeepSeek 官方兼容接口 |

本项目是联网部署器。下载到几 MB 的部署 ZIP，不代表所有镜像、模型已经在其中。

## 2. 下载与解压

1. 从仓库的 **Releases → Latest** 下载 `DSdeploy-v1.2.0-windows.zip`，同时下载 `SHA256SUMS.txt`。
2. 如需核对完整性，可在 PowerShell 中执行：

   ```powershell
   Get-FileHash .\DSdeploy-v1.2.0-windows.zip -Algorithm SHA256
   ```

   将输出与 SHA256SUMS 中同名文件的摘要比较。
3. 右键 ZIP，选择“全部解压缩”，放在固定、可写的目录，例如 `D:\Apps\DSdeploy`。不要直接在 ZIP 预览窗口里运行脚本。
4. 找到包含 `一键启动.cmd`、`Deploy.ps1` 和 `compose.yaml` 的文件夹。后续数据都相对这个文件夹保存。

## 3. 准备 Docker Desktop

### 新安装

1. 双击 `安装Docker.cmd`。
2. 脚本把官方安装器下载到 `runtime/downloads`，检查数字签名，然后打开 Windows 安装授权提示。
3. Docker 程序目标位置为 `runtime/DockerDesktop`，WSL 数据盘目标位置为 `data/docker-desktop`。
4. 按安装器提示启用所需的 WSL2/虚拟化组件。如要求重启 Windows，先重启。
5. 打开 Docker Desktop，完成首次设置，等待引擎显示运行中，并确认处于 **Linux containers** 模式。

如果任务管理器“性能 → CPU”显示虚拟化未启用，需按电脑厂商说明在 BIOS/UEFI 中启用；此设置无法由部署包通用代办。

### 机器已有 Docker

本包采用包内数据盘约定。若 Docker 的数据盘在其他位置，启动器会在下载镜像前停止，并给出目标目录。
可在 Docker Desktop 的 **Settings → Resources → Advanced → Disk image location** 中选择包内 `data/docker-desktop`，应用更改后重试。
这个设置管理的是当前 Docker Desktop 的数据盘，涉及已有镜像与容器；本包不会自动迁移、重装或删除你的其他部署。

Docker Desktop 和 WSL 仍会保留必要的 Windows 系统设置与日志，因此整个方案不是无需安装的绿色便携软件。安装后请固定目录位置。

## 4. 分别准备镜像与导入配置

先双击 `下载准备镜像.cmd`。此步下载或导入 AstrBot、NapCat、Ollama，构建四插件依赖，并准备 bge-m3；无需填写 QQ、API Key，不启动机器人。下载失败后仍运行这个入口重试。

完成后双击 `导入初始配置.cmd`，依次填写：

| 提示 | 填什么 |
|---|---|
| 你的 QQ 号 | 你要和机器人聊天的账号，用于主人权限和默认主动陪伴目标 |
| 机器人小号 QQ 号 | NapCat 即将登录的账号，必须与主人 QQ 不同 |
| 允许群聊的群号 | 可选，逗号分隔。不填只允许主人私聊；填写后仅对这些群开放历史、低概率主动接话和陪伴配置 |
| 模型 API 地址 | 默认回车使用 `https://api.deepseek.com/v1`；第三方兼容接口按提供方文档填写 |
| 模型名称 | 默认回车使用 `deepseek-flash`；接口使用模型 ID，不是随意填写产品展示名 |
| API Key | 粘贴自己的 Key。输入时不会显示字符，输入完按回车 |

不要把 API Key 发进 QQ、Issue、截图或公开仓库。首次配置写入本机 private 和 data，后续启动不重复覆盖面板中的修改。

配置导入只创建初始模型、主人权限、OneBot、人格和插件配置，不下载、构建镜像，不启动 QQ。已有配置继续保留。

两步完成后，双击 `一键启动.cmd`。它只启动本地已有环境；缺少镜像或配置时，会提示运行对应入口，不会自行重新下载或覆盖。

以后升级按 [分步部署与升级](分步部署与升级.md)：可以只升级配置，也可以单独更新镜像。
## 5. 登录面板和机器人 QQ

初始凭据保存在 `private/面板登录信息.txt`：

- **AstrBot**：打开 `http://127.0.0.1:6185`，用户名为 `astrbot`，使用文件中的随机密码。
- **NapCat**：打开 `http://127.0.0.1:6099/webui`，使用文件中的随机 Token。

在 NapCat 中显示登录二维码，用手机 QQ 扫码。**确认登录的账号正是首次填写的机器人小号**，完成 QQ 要求的设备验证。
初始凭据文件不跟随你以后在面板修改的密码更新；修改后以面板实际密码为准。

OneBot 连接已自动配置为：

```text
NapCat → ws://astrbot:6199/ws → AstrBot
```

双方使用同一个随机连接密钥。在两个容器中不要把 `astrbot` 改成 `127.0.0.1`；容器内的回环地址不是另一个容器。

## 6. 第一次聊天与逐层验收

1. 用主人 QQ 添加机器人小号为好友。
2. 私聊发送“你好，大肥鱼”。QQ 实际收到回复才代表基本聊天链路通过。
3. 若没有回复，先确认 NapCat 已登录、反向 WS 已连接；再在 AstrBot 中单独测试模型，最后检查默认主人 QQ 和白名单。
4. 默认只允许主人私聊。需要其他用户或群聊时，在 AstrBot 的访问控制中明确添加对应会话/群；不要用空白名单代表“拒绝其他人”，上游的空白名单含义是不限名单。

已预设：

- 聊天模型 ID：`deepseek/deepseek-flash`。
- 向量模型 ID：`bge_m3_local`。
- 人格 ID：`dafeiyu`。请在 AstrBot 的人格页面编辑它；修改 bootstrap/persona.txt 只影响全新的首次初始化。

## 7. 验证和调整长期记忆

1. 在 AstrBot 插件页确认 **LivingMemory 2.7.3** 已加载。
2. 确认插件 Embedding Provider 为 `bge_m3_local`，总结模型为你的聊天模型 ID。
3. 在 QQ 发送 `/lmem status`，检查记忆系统状态。
4. 告诉机器人一个适合保存的测试偏好，并明确说“请记住”。在 LivingMemory 的插件页面查看是否出现实际记忆记录，不能只看机器人的口头承诺。
5. 在同一 QQ 会话中开启新的对话，再询问该偏好；重启服务后重复测试，区别长期存储与当前聊天上下文。

默认每 10 轮对话触发总结，启用主动保存和主动召回工具，按人格与会话隔离，只为主人私聊开放记忆访问。
总结、反思和主动保存可能使用聊天 API；向量计算由本地 bge-m3 完成。更换向量模型后，历史索引可能需要重建，请按 LivingMemory 上游文档操作。

## 8. 验证和调整主动陪伴

在 AstrBot 的 **Proactive Chat / 主动消息** 插件配置中查看：

| 设置 | 默认值 |
|---|---|
| 主动目标 | 仅主人 QQ 私聊 |
| 常规触发间隔 | 120–240 分钟 |
| 免打扰 | 每天 23:00–08:00，Asia/Shanghai |
| 最大未回复次数 | 3 |
| 启动自动任务检查 | 60 分钟 |
| 群主动消息 / TTS / 独立 WebUI / 遥测 | 关闭 |

测试时可暂时把间隔调短，并选择免打扰以外的时段；确认 QQ 真的收到消息后，再恢复常规间隔。触发还受已有会话、未回复次数、QQ 在线状态及模型可用性影响。
暂时不需要主动联系时，在插件配置中关闭私聊主动消息。此功能不是必须保持开启的部署前提。

## 9. 日常启动、停止和检查

| 入口 | 操作 |
|---|---|
| 下载准备镜像.cmd | 准备或补齐镜像、依赖、向量模型；复用已锁定版本 |
| 更新镜像.cmd | 主动拉取上游新版，不导入配置 |
| 导入初始配置.cmd | 创建初始配置，不下载镜像 |
| 一键启动.cmd | 只启动已有环境和配置，打开面板 |
| 一键停止.cmd | 停止服务，保留登录状态和聊天数据 |
| 查看状态.cmd | 显示三个容器的状态 |
| 查看日志.cmd | 显示最近日志并跟随，Ctrl+C 退出 |
| 环境检查.cmd | 检查文件、Docker 引擎、Linux 模式和 Compose 结构 |
| 备份数据.cmd | 暂停业务后生成 ZIP，再恢复之前正在运行的服务 |
| 下载镜像包.cmd | 在联网电脑下载并导出三个基础镜像 |

仅显示容器 Up 或页面打开，不代表 QQ 或模型 API 已通过验收。

## 10. 备份与恢复

备份 ZIP 位于 backups，包含 data/astrbot、data/napcat、data/qq、private 以及镜像锁，保留原相对路径。
它不复制正在运行的 Docker VHD、镜像缓存或可以重新下载的 Ollama 模型。失败文件使用 .partial 扩展名。

恢复时：

1. 先用一键停止停止目标部署。
2. 将当前三个业务数据目录和 private 改名保留，避免覆盖掉较新的数据。
3. 把备份 ZIP 解压到包含 Deploy.ps1 的根目录，确认得到 data/astrbot 等原路径。
4. 保留原 Docker 安装和 data/docker-desktop；不要用业务备份替换正在使用的虚拟磁盘。
5. 启动并重复 QQ、模型与记忆检查。跨电脑恢复还需要准备 Docker 和相应模型。

备份中含密钥、聊天与登录信息，不能附在公开 Issue 中。

## 11. 国内镜像源及本地导入

默认 DaoCloud，不修改整台机器的 registry-mirrors。需要切换时，在部署目录的 PowerShell 中运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Deploy.ps1 -Action PrepareImages -ImageSource 1ms
# 或使用原始 Docker Hub
powershell -NoProfile -ExecutionPolicy Bypass -File .\Deploy.ps1 -Action PrepareImages -ImageSource Official
```

已有 compose.lock.json 时，PrepareImages 继续使用锁定版本。明确升级及切换源请用 `-Action UpdateImages -ImageSource 1ms`；旧锁自动备份，不需手动改名。
网络畅通的另一台 Docker 电脑可运行“下载镜像包.cmd”，将生成的 offline/images.tar 和校验文件一起放回目标部署目录。导入方式见 [下载说明](../offline/下载说明.md)。
这只是基础镜像离线导入，插件依赖、向量模型首次准备和聊天 API 仍可能需要网络。

如果本机代理使用 Fake-IP，本包会尝试为官方模型域名查询公网地址，生成仅作用于 Ollama 的 compose.dns.json。网络变更后遇到模型更新问题，可停止服务、将该文件改名，再重试；不会改系统 DNS 或关闭地址校验。

## 12. 更新与回退

1. 先备份业务数据，保留当前 compose.lock.json。
2. 下载新部署包，将源码文件更新到原目录，保留 data、private、runtime 和 backups。
3. 先停止服务。依赖变化运行“下载准备镜像.cmd”；主动更新框架/协议镜像运行“更新镜像.cmd”。配置迁移单独运行“升级陪伴配置.cmd”，最后一键启动。详细流程见 [分步部署与升级](分步部署与升级.md)。
4. 已安装的插件源码不会因简单覆盖部署 ZIP 而被强行替换；插件升级按 AstrBot 插件页和上游说明执行。
5. 回退要同时考虑旧镜像锁与对应数据备份。上游升级可能迁移数据库，不能只换回镜像就保证兼容。

## 13. 常见故障

| 现象 | 先检查什么 |
|---|---|
| Docker 未安装/引擎未就绪 | 启动 Docker Desktop，完成首次设置；必要时重启 Windows |
| 提示数据盘不在包内 | 检查 Disk image location，确认 data/docker-desktop 下存在实际 VHDX |
| 提示不是 Linux containers | 切换 Docker Desktop 的容器模式 |
| 镜像下载 EOF/超时 | 默认重试三次；换 DaoCloud/毫秒/原站或使用本地镜像导入 |
| 插件构建依赖冲突 | 保留完整报错和镜像锁；不要直接强制升级基础镜像中的依赖 |
| bge-m3 下载被拒绝/非公网地址 | 检查 Fake-IP 修正输出、代理与 DNS；保留日志中的错误类型，遮住签名 URL |
| 两个面板端口被占用 | 先停止旧部署；本包固定使用 6185/6099，一台机器默认运行一份 |
| QQ 在线但不回复 | 依次确认反向 WS、模型测试、主人 QQ、白名单和实际会话 |
| API 401 | 地址或 Key 不正确 |
| API 429 | 阅读错误正文；余额不足和请求限流需要分别处理 |
| 没有主动消息 | 主人会话、自动触发、免打扰、未回复次数、在线状态和模型是否可用 |
| 新对话忘记偏好 | 先确认数据库确实保存，再检查同一会话/人格、Embedding 和召回结果 |

## 14. 提交问题前

提供 Windows/Docker 版本、出错步骤、已遮盖敏感内容的错误片段，以及固定镜像/插件版本。不要上传 private、data、backups、二维码、完整设置文件或真实聊天记录。
实际已测试的范围与未完成的 QQ/API 验收见 [验证记录](验证记录.md)；公开文件和数据流说明见 [隐私说明](隐私与发布范围.md)。

## 15. v1.0 用户升级陪伴功能

1. 解压新包覆盖原源码文件，保留 data/private/runtime/backups。
2. 先停止服务，运行“下载准备镜像.cmd”，等待表情包与签到插件依赖构建完毕。
3. 运行“升级陪伴配置.cmd”，它会先备份，再更新短句分段、最近聊天上下文等表达设置。已有自定义人格保留；只有完全未修改的 v1.0 默认人格自动升级。
4. 如果要恢复你自己备份中的表情图片，运行“导入我的表情库.cmd”。已有图库不会被覆盖，原聊天、账号和云同步配置不会一起导入。
5. 一键启动服务。需要进一步增强时，按 [活人感方案](活人感方案.md) 的清单逐项验证；不要一次叠加多个主动消息或表情发送插件。
