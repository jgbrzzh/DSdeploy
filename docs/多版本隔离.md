# 旧版不动，新目录独立运行（v1.3）

## 推荐用法

1. 原 v1.0 目录、文件、配置和启动入口全部保留，不在旧目录覆盖本版。
2. 将新版包解压到另一个空目录，例如旧版 D:\Bots\Whale-v1.0，新版 D:\Bots\Whale-new。
3. 新目录运行“实例设置.cmd”，生成本目录的 private/instance.json 和“本实例面板地址.txt”。也可以直接准备镜像，首次会自动创建实例设置。
4. 已有 Docker 直接复用，无需安装第二套、迁移数据盘或停止旧版。
5. 新目录依次运行下载准备镜像、导入初始配置、一键启动。以后从哪个目录点击启动/停止/升级，就只操作哪个实例。

初次分配的面板端口取自不同目录的哈希，AstrBot 在 20000–28999、NapCat 在 30000–38999；会避开当前监听端口，默认不占旧版的 6185/6099。首次创建时也可明确指定：

```powershell
powershell -File .\Deploy.ps1 -Action ConfigureInstance -AstrBotPort 26186 -NapCatPort 26010
```

以后沿用已保存端口。若需要调整，请先停止该实例，再修改其 private/instance.json 中两个端口，保持不同且空闲；不要改 project/image/root。启动会读取新地址。

## 隔离范围

| 项目 | 处理方式 |
|---|---|
| Compose 项目/容器/网络 | 目录唯一 dsdeploy-哈希，与旧版 dsdeploy 分开 |
| AstrBot 运行镜像标签 | dsdeploy-astrbot-哈希:local，构建新版不覆盖旧版 dsdeploy-astrbot:local |
| 配置/聊天/记忆/QQ 登录/模型数据 | 各自根目录下 data，相互独立，不挂载另一实例目录 |
| 凭据/镜像锁/实例设置/备份 | 各自目录保存 |
| 面板端口 | 每实例独立，容器内部端口和服务 DNS 不变 |
| Docker 引擎/基础镜像层/电脑资源 | 共用现有 Docker；不是两个虚拟机或两个 Docker 引擎 |

基础镜像可复用；Ollama 模型文件位于各自 data/ollama，首次可能分别下载。没有自动跨目录链接模型或聊天库。

真正同时在线请给两个实例使用不同 QQ 小号；同一个 QQ 的登录设备限制仍可能顶号。若只是比较两个版本，可以交替登录，但数据和入口仍分开。

## 防误操作与数据副本

本版检测到旧数据却没有实例身份时，会停止操作，避免用新入口误管旧项目。将新启动器直接覆盖到 v1.0 目录，不是本版推荐的并行方式。

不要复制旧 private/instance.json 到新目录。实例记录所属绝对目录，复制后会拒绝启动/停止，防止误操作原容器。安装后不要随意移动目录。

如果需要使用旧数据的副本：先备份旧数据，停止旧版以取得一致快照；仅将业务数据与必要凭据复制到新目录，不链接目录、不复制实例身份。确认旧版备份保留后，对副本显式运行：

```powershell
powershell -File .\Deploy.ps1 -Action ConfigureInstance -AdoptData
```

然后准备新目录的独立运行镜像并启动。新上游可能迁移副本数据库，因此不能再将新数据库直接覆盖回旧版。一般体验新版本直接用全新配置更省事。

容器分离可以避免入口误停、覆盖镜像及串用数据，仍会共享 CPU、内存、磁盘和 Docker 服务。停止整个 Docker Desktop 会同时停止所有实例；请日常使用各目录的“一键停止.cmd”。
