# 分步部署与升级（v1.2）

## 三步职责

| 入口 | 网络与镜像 | 业务配置 | 服务 |
|---|---|---|---|
| 下载准备镜像.cmd | 首次下载/导入镜像，构建插件依赖，准备 bge-m3；以后复用镜像锁 | 不读取 QQ/Key，不生成或迁移机器人配置 | 仅临时启动 Ollama 准备模型，恢复其原运行状态 |
| 更新镜像.cmd | 主动拉取上游最新版本，备份旧镜像锁并写入新锁，按需构建 | 保留现有配置、人格、记忆、QQ 登录数据 | 不自动替换正在运行的 AstrBot/NapCat；下次启动应用新版 |
| 导入初始配置.cmd | 只使用准备好的本地镜像，不拉取、不构建 | 首次填写 QQ/Key 并生成配置；已有配置保留 | 不启动机器人；已有部署操作时先备份并恢复原运行服务 |
| 升级陪伴配置.cmd | 不拉取、不构建；缺少新依赖时提示准备镜像 | 先备份，再应用陪伴预设；保留自定义人格、Key、身份和时段 | 暂停后恢复原运行服务 |
| 导入内置表情库.cmd | 不拉取、不构建 | 安装两套公开图库，保留已有同名包及绑定 | 先备份并恢复原运行服务 |
| 一键启动.cmd | 禁止自动拉取和构建 | 不运行初始化，不重导配置 | 使用本地镜像启动并打开面板 |

“导入初始配置”是创建本包所需配置，不是将陌生备份里的账号/聊天整库恢复。私人表情仍使用“导入我的表情库.cmd”。

## 第一次部署

1. 安装或启动 Docker，确认数据盘在包内。
2. 下载准备镜像：此时无需提供 QQ 或 Key，网络较好时可以提前完成。
3. 导入初始配置：填写你自己的账号和模型接口，自动装入随包的两套公开图库。
4. 一键启动，进入 NapCat 扫码，再完成 QQ 对话验收。

## 已有部署升级

先运行“备份数据.cmd”，再“一键停止.cmd”。将新版程序覆盖到原目录；保留 data、private、backups、runtime、compose.lock.json 和 compose.dns.json。

- **只改人设或陪伴配置**：若新版没有依赖变化，直接“升级陪伴配置.cmd”，然后一键启动。不需要更新镜像。面板里的个人定制建议直接在面板修改。
- **新版插件或依赖变化**：运行“下载准备镜像.cmd”，沿用已有基础镜像锁，仅在依赖摘要变化时重新构建；再按需要升级陪伴配置并启动。
- **主动升级 AstrBot/NapCat/Ollama**：运行“更新镜像.cmd”，然后一键启动。原镜像锁备份到 backups/镜像锁-时间.json；业务配置没有自动重导。
- **只是重启**：直接“一键启动.cmd”。即使初始化脚本存在，也不会在启动时执行。

v1.1 → v1.2：现有镜像、构建状态和业务配置可复用；新增入口不要求重新填写 QQ 或 Key。启动时发现新依赖缺失会给出明确提示。

新版上游可能自行迁移数据库；升级前的业务备份必须保留。旧镜像锁只记录版本，不能代替数据库恢复。不要删除正在使用的旧镜像后再尝试回退。

## 命令行和镜像源

```powershell
# 仅准备运行环境，复用锁定版本
powershell -File .\Deploy.ps1 -Action PrepareImages -ImageSource DaoCloud
# 明确更新上游镜像，可更换镜像源
powershell -File .\Deploy.ps1 -Action UpdateImages -ImageSource 1ms
# 配置与启动分别运行
powershell -File .\Deploy.ps1 -Action InitializeConfig
powershell -File .\Deploy.ps1 -Action Start
```

offline/images.tar 只在首次未锁定版本的准备操作中导入；明确更新镜像会重新拉取，不会误用旧离线包。“下载镜像包.cmd”仍是给另一台机器搬运基础镜像的导出入口，与本机准备入口不同。

图库文件位于 meme-packs，通过只读目录独立挂载，不进入 Docker 构建上下文。仅更新图库后运行“导入内置表情库.cmd”即可；已有同名包不会被覆盖，版本更新或合并请在插件管理页处理。
