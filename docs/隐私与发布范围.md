# 隐私与公开发布范围

公开仓库和 Releases 使用明确的文件清单发布，不从整个工作目录递归打包。

## 可以公开的内容

- 部署脚本、Dockerfile、Compose 模板、原创角色提示词。
- 安装、配置、排错、备份恢复、维护与验证说明。
- 固定版本的第三方插件源码、原始许可证和来源校验清单。
- 合成数据测试、镜像摘要、依赖版本及不含凭据的检查结果。

公开测试中出现的数字用户 ID 和偏好均为固定合成数据，不是真实 QQ 用户信息。第三方源码归档中的原作者署名与公开联系方式属于上游来源信息，按原许可证保留。

## 不发布的内容

| 目录/文件 | 可能包含的内容 |
|---|---|
| private/ | API Key、面板密码、OneBot Token、Docker 客户端凭据 |
| data/ | QQ 登录状态、聊天记录、长期记忆、插件运行数据库、模型、Docker 虚拟磁盘 |
| backups/ | 上述业务数据及凭据的备份 |
| runtime/ | 下载器、安装目录、临时文件和缓存 |
| .research/、.runtime-test/ | 研究副本与本地临时验证环境 |
| offline/*.tar | 用户导出的镜像档案，默认不提交源码仓库 |
| compose.lock.json、compose.dns.json | 运行时版本锁和当前网络生成的域名映射 |

`.gitignore` 只能保护尚未跟踪的文件。维护者仍需检查暂存区；已经进入 Git 历史的凭据不能仅靠增加 ignore 规则撤回。

## 本项目的发布检查

1. 使用 `tools/audit_public.py` 检查发布清单及 ZIP 内部，排除运行目录、常见凭据格式、本机用户名路径及设备名。
2. 部署包使用 `tools/package.py` 的固定清单构建，重新校验每个插件归档的 SHA-256。
3. 发布前审查 `git diff --cached` 与 `git ls-files`，仅推送审查后的源码。
4. Git 提交使用 GitHub 的 noreply 邮箱，不使用维护者的私人邮箱。GitHub 仓库所属账号、公开提交和发布者仍按 GitHub 的正常机制显示。

## 使用时的数据流

- API Key 通过隐藏输入读取，随后保存在本机配置中，不是加密保险库；不要把 private、data 或备份分享给他人。
- DeepSeek 对话、总结与主动消息会发送到你配置的 API 服务；召回的记忆也可能进入该请求。
- bge-m3 向量计算在本机 Ollama 内完成，初次模型下载需要网络。
- 管理端口仅绑定本机回环地址。主动陪伴默认只面向首次填写的主人 QQ，会话与人格隔离开启。
- Fake-IP 修正只查询官方模型下载域名的 DNS 信息，不发送聊天内容、API Key 或 QQ 登录凭据。
