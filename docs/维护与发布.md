# 维护、验证与发布

普通用户请使用 [操作流程](操作流程.md)。本页面向源码维护者；Python 仅用于检查与打包，不是部署包最终用户的额外前提。

## 本地开发环境

在仓库根目录创建独立环境，并将缓存留在项目内：

```powershell
New-Item -ItemType Directory -Force .research\tmp | Out-Null
$env:TEMP = Join-Path $PWD '.research\tmp'
$env:TMP = $env:TEMP
$env:PIP_CACHE_DIR = Join-Path $PWD '.research\pip-cache'
python -m venv .research\verify-venv
.\.research\verify-venv\Scripts\python.exe -m pip install sqlmodel aiosqlite greenlet deprecated pyyaml
```

## 检查发布范围

```powershell
python tools/audit_public.py
```

发布文件清单由 tools/public_files.py 定义。不要使用不经审查的整目录上传，也不要将 ignore 规则当成已经清除 Git 历史的证明。
扫描器同时检查 vendor 嵌套 ZIP。固定上游测试中的 `test`/“张三”目录例子经过明确审查后保留，不代表忽略任意用户目录。

## Windows 启动器回归

```powershell
python tests/verify_launcher.py
```

该测试调用真实 Windows PowerShell 5.1，但 Docker CLI 与两个 HTTP 页面为模拟对象。覆盖中文/空格路径、包内数据盘限制、多个镜像摘要、stderr 进度、缺失模型分支、重复启动、失败中止和备份目录结构。
测试文件位于 .research 中，结束后移除；它不会安装 Docker、登录 QQ 或调用收费 API。

## 真实上游子模块集成检查

将固定提交的 AstrBot 源码准备到 .research/AstrBot：

```powershell
git clone https://github.com/AstrBotDevs/AstrBot .research/AstrBot
git -C .research/AstrBot checkout 832fc6d98ac25facd54b07424c16067435c118e6
.\.research\verify-venv\Scripts\python.exe bootstrap/install_plugins.py vendor .research/extracted-plugins
.\.research\verify-venv\Scripts\python.exe tests/verify_source.py
```

此检查使用实际默认配置、密码校验和 SQLite ORM，但绕过应用包的全局启动。它不能代替容器或 QQ 验收。

## 构建部署 ZIP

```powershell
python tools/package.py
python tools/audit_public.py --archive dist/QQ大肥鱼一键部署包.zip
```

构建器只复制固定清单，重新校验 ZIP 结构与两个插件源码的 SHA-256。输出 ZIP、独立 SHA-256 文件和包内逐文件清单。
GitHub Release 的 ASCII 名称副本为 DSdeploy-v版本号-windows.zip，发布时同时附 SHA256SUMS.txt。更新 VERSION、文档和发布说明后再生成新版本，不能只改压缩包文件名。

## 提交与公开发布

1. 只暂存 tools/public_files.py 中的源码清单，保持 private、data、backups、runtime 和本地测试目录未跟踪。
2. 执行 `python tools/audit_public.py --staged`。
3. 检查 `git diff --cached --stat`、`git diff --cached` 和 Git 提交邮箱；使用 GitHub noreply 邮箱。
4. 提交后执行 `python tools/audit_public.py --tracked`，推送公开仓库。
5. 等待 GitHub Actions 检查通过，再创建版本标签和 Release，附 ZIP 与 SHA256SUMS。
6. 从 GitHub 下载实际发布的 ZIP，核对其 SHA-256 与本地产物一致。

## 真实部署验证

在独立、允许清理的测试环境解压发布 ZIP，不沿用个人 QQ、聊天库或 API 凭据。先验证镜像构建、插件加载、本地向量、测试记忆重启召回和备份，再单独安排真实账号/API 验收。
tests/real_docker_bridge.py 可将 Windows 启动器连接到明确指定的临时 WSL Docker；必须设置 DSDEPLOY_TEST_DISTRO。它只做路径转换，不模拟 Docker。测试发行版的创建、用途、保存位置及清理应由操作者明确管理，不要使用日常环境做破坏性清理测试。

tests/probe_real_services.py 仅针对 .runtime-test/package 中的合成配置工作，会在临时记忆库导入一条合成记录。不要把它指向真实业务库。

## 上游更新

替换插件归档时，保留完整源码与 LICENSE，更新 vendor/manifest.json 的仓库、版本、提交和摘要。重新做源码集成、隐私检查与实际插件加载验证。
从新镜像构建后记录镜像摘要；镜像、插件和数据迁移各自有兼容边界，不能仅用“latest”声称所有组合均可运行。
