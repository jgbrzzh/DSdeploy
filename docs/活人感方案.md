# 活人感配置：备份迁移与后续增强

更新日期：2026-10-27。这里区分“迁移了什么”“哪些已验证”和“还可以做什么”，不把提示词修改等同于真实 QQ 聊天效果已经验收。

## 本次按备份迁移的内容

检查私人备份后，只将可复用的人格和表达参数迁入公开模板。没有导入整个数据库，也没有恢复原使用者的 QQ、群号、API Key、云存储凭据、对话、记忆或附件。

| 层次 | v1.0 默认 | v1.1 改动 |
|---|---|---|
| 人格 | 简短的通用鲸鱼娘设定 | 以备份当前选中的大肥鱼人格为依据，保留短句、网络口语、玩梗、轻微吐槽、认真求助时收起嘲讽的节奏 |
| 普通回复 | 整段发送 | 开启备份同款短句分段，1.5–3.5 秒间隔，150 字阈值，按配置清理句末标点 |
| 主动上下文 | 仅 LLM 对话历史 | hybrid，结合最近 20 条真实平台流水、机器人自己的回复和当前人格 |
| 主动表达 | 普通问候式开场 | 主动消息也使用分段，接最近话题，保留事实边界，不捏造共同经历 |
| 未回复上限 | 1 | 新部署采用备份的 3；已有用户自己改成其他值时，升级保留其值 |
| 群聊识别 | 基础开关 | 注入发送者/群名和群聊历史；只有首次明确填写的群号才放行 |
| 表情 | 没有表情插件 | 增加 meme_manager 5.2.9，上下文情绪判断、每次最多 1 张、允许主动消息链路选图 |
| 互动 | 没有签到 | 增加积分签到 1.3.2，管理员由本次部署的主人 QQ 生成 |

备份人格中“扮演真人”“刻意反串招黑”和无来源的亲历示例没有原样照搬；保留群友语气，但直接被问技术身份时如实说明，也不假装已经搜索、看视频或执行了工具。
原备份的本机执行权限和搜索密钥不是活人感必需条件，没有随表达配置开启。角色的兴趣与评价口吻也不等于真实专业资历。

## 如何使用

**新部署：**解压最新版，依次运行“下载准备镜像.cmd”“导入初始配置.cmd”“一键启动.cmd”。四个插件和表达配置自动初始化；群号可选，不填仍然只允许主人私聊。

**已有 v1.0/v1.1 部署：**原目录保留，在独立新目录安装最新版。需要旧数据时先备份，再按多版本隔离说明复制业务副本并建立新身份；准备镜像后，可对副本运行 `升级陪伴配置.cmd`，最后一键启动。
该入口先暂停本包服务并备份，再应用表达设置；保留模型密钥、QQ 身份、白名单、主动时段和自定义人格。只有人格内容仍完全等于 v1.0 默认值时，才自动替换为新默认人格。
你已自行编辑的人格继续保留；若确实想使用新大肥鱼文本，在 AstrBot 人格页人工选用 bootstrap/persona.txt 的内容。

## 表情库必须单独说明

表情插件代码与两套公开图库现已随包提供：大肥鱼 138 张、菲比啾比 101 张。来自对应公开上游，未从私人备份分发图片；来源与固定提交见 [资源说明](../meme-packs/README.md)。新部署导入配置时自动安装并同时启用两套资源。

- 已有部署：运行“导入内置表情库.cmd”。先备份，不覆盖已有同名包及修改，保留已有默认/会话/人格绑定；需要时在插件管理页选择两套库。
- 复用你自己的旧库：首次启动后运行 `导入我的表情库.cmd`，选择你自己的 AstrBot 备份 ZIP。它先备份当前业务数据，仅提取表情图片，建立本地 personal-import 包；不恢复聊天、账号、云同步密钥或旧索引。
- 当前已经有表情图片时，导入器会拒绝覆盖，改用插件界面的资源包导入/合并功能。
- 本地输入 ZIP 会暂存在 private/meme-import.zip，始终排除公开发布和业务备份。不要将整个 private 分享出去。

情绪判断会使用所选聊天模型，可能增加 API 调用；向量语义选图和自动收集默认关闭，需要时再在插件页启用。不要同时安装多套自动表情插件，否则可能重复发图。

## 网上继续核对的增强方向

以下根据上游文档与源码整理；收益是对对话体验的工程判断，仍需真实聊天 A/B 检查。

### 1. 先让它等你说完：消息合并与打断

连发“等一下”“刚才说错了”“是明天”的时候，逐条立即回答往往显得机械。
[Message Merger](https://github.com/ahuai114514/astrbot_plugin_message_merger) 提供零等待合并：第一条直接进入模型，追加纯文本时取消旧请求并重组；按会话和用户隔离，不合并不同群成员，也不处理图片、引用和文件。
[TurnFlow](https://github.com/Yuimi-chaya/astrbot_plugin_turnflow) 则提供私聊动态防抖、未完成回复中断、可选撤回和历史回滚。

建议下一批先在私聊选择其中一个测试，别同时装。必须测试“连发 + 记忆写入 + 模型工具调用”，确认被取消的旧回复不会留下错误记忆、重复执行工具或串会话。本版没有默认加装，避免未经验证地改动正在工作的消息主链。

### 2. 连续生活状态比反复寒暄更有用

[Private Companion](https://github.com/menglimi/astrbot_plugin_private_companion) 提供角色状态、生活日程、日记及主动联系。
核对时主仓库 README 明确提示 7.0 处于迁移测试状态，并建议保持 6.7；[6.7 只读备份](https://github.com/menglimi/astrbot_plugin_private_companion_legacy_6_7_0) 可用于研究稳定行为。

适合的下一步是让“最近在忙什么”“上次话题后来怎样”有持久状态支撑，明确区分角色创作、计划与真实工具完成记录。
接入前先选定唯一主动发送调度器，或验证上游桥接；不要直接叠加 Private Companion 和 Proactive Chat 的两套闹钟。本版保留备份原有 Proactive Chat，未默认混入迁移中的大系统。

### 3. 表情用在态度上，而不是每句话装饰

[meme_manager](https://github.com/anka-afk/astrbot_plugin_meme_manager) 已提供上下文选图、资源包选择和主动消息触发范围，本版直接复用。
另一个候选 [SendEmojis](https://github.com/L1ke40oz/astrbot_plugin_sendemojis) 支持按情绪分类、概率和发送位置控制；因为与本版表情能力重叠，只列为替换方案。
先让图库少而贴切，避免连续同一张、误把自述难过当成安慰对方。图片细节没有依据时不要编造。

### 4. 发送节奏需检查消息组件兼容

备份中的分段与标点清理能改善普通短句节奏，但短代码块、公式和正式说明需要保留格式。
上游 [Issue #10047](https://github.com/AstrBotDevs/AstrBot/issues/10047) 报告原生 QQ Face 与分段消息被切碎的情况；它与图片表情不是完全相同的链路。
建议真实测试纯文字、文字加图、原生 Face、代码块四种输入；遇到拆坏，先关闭相应分段或标点清理，不盲目加第二层输出处理。

### 5. 工具和记忆要提供事实，不要靠提示词假装经历

当前已开启时间、发送者和群名信息，记忆按会话/人格隔离。对“你还记得吗”先查记忆，有工具结果才说做过某事。
搜索、读视频、语音或浏览器可以以后按真实需求接，但都需要验证实际服务、权限及成本；不为了让角色像真人而编造已发生的行为。

## 建议的对话验收表

| 场景 | 观察点 |
|---|---|
| “6”“笑死”之类轻聊天 | 允许短回应，不展开成总结和客服追问 |
| 连续改口 | 不同时回答旧问题和新问题；未来消息合并改动要重点测试 |
| 真正摔伤或情绪低落 | 能停下玩梗，认真且简短回应 |
| 新对话问旧约定 | 真正召回记忆，不凭空熟悉 |
| 刚聊过某游戏后收到主动消息 | 自然续话题，不固定“今天过得怎么样” |
| 代码、列表或精确格式要求 | 不因短句/清理规则损坏必要内容 |
| 群中两人连续讲话 | 分清谁说什么，不把身份和记忆串给另一个人 |
| 表情资源包为空/没有合适图 | 用文字继续，不输出内部分类标记 |

最终“有没有活人感”仍以使用者在 QQ 的主观体验和实际消息为准。当前配置回归与容器加载检查只能证明接线与兼容性，不能替代试听式聊天验收。
